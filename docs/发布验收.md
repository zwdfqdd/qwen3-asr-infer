## 5. CER 门禁

```bash
DO_INSTALL=0 DO_DOWNLOAD=0 bash scripts/run_verify.sh
```

默认通过 `/chinese_asr` 验证发布契约。`--baseline-cer` 下必须满足：参考覆盖全部选中音频、
每条参考非空、计分样本数等于输入样本数、总参考字符大于 0。保存完整输出作为发布证据。
阈值 `0.05` 是项目示例，正式阈值必须由业务验收集确定。

## 6. 性能门禁

按 [性能调优文档](性能调优.md) 在目标 Linux/CUDA 环境至少执行短音频和业务最长音频：

```bash
python tests/test_service.py --api-mode chinese-asr \
  --audio test_data/audio_16000_10s.wav --concurrency 96 --total 2000
```

发布标准应明确：成功率、P95/P99、audio_s/s、GPU 显存峰值和 CER。v1.0.0 默认 `3/64`；
若改为 `3/96`，必须补混合时长回放证据。

## 7. 上线步骤

1. 从 `v1.0.0` tag 构建不可变镜像，记录镜像 digest。
2. 在新实例安装精确依赖并校验模型 manifest；不要复用其他 revision 的模型目录。
3. 先启动 vLLM 和网关，等待 `/health` 返回版本 `1.0.0` 与预期模型名。
4. 执行短音频、长音频、热词、错误契约和 CER 冒烟。
5. 接入层先小比例引流，观察 5xx、P95/P99、waiting requests、GPU 显存和取消/超时。
6. 达到观察窗口且无回归后逐步扩流；旧实例保持可回退，不立即删除模型或镜像。

## 8. 回滚流程

回滚是可逆的实例/流量切换，不对线上目录执行 `git reset --hard` 或覆盖模型文件：

1. 在 Gateway/LB 停止向 v1.0.0 新实例继续扩流，并将流量切回上一已验收镜像。
2. 确认上一实例 `/health`、单条转写和关键指标正常后，再摘除异常实例。
3. 若仅配置回滚，使用上一版本完整环境变量集重建实例，避免混用新旧参数。
4. 若模型 revision 回滚，使用上一 revision 对应的独立模型目录和 manifest；禁止在原目录覆盖。
5. 保存故障时的 vLLM/网关日志、指标、请求 ID、模型 manifest 和镜像 digest用于复盘。
6. 修复后重新执行本文件全部门禁，通过新 tag/镜像再次发布，不在原 tag 上覆盖。
