# 使用说明（v1.1.0）

## 1. 环境准备

目标平台为 Linux + NVIDIA CUDA。必须创建独立虚拟环境，不与 Paraformer、funasr、
TensorRT 或旧 Transformers 5.x 环境混装。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-infer.txt
python -m pip install -r requirements-aligner.txt
python -m pip check
python -c "import vllm, transformers; print(vllm.__version__, transformers.__version__)"
```

锁定依赖为 `vllm[audio]==0.16.0`、`transformers==4.57.6`、`aiohttp==3.13.3`、
`soundfile==0.13.1`、`psutil==7.0.0` 和 `qwen-asr==0.0.6`。默认开启 ForcedAligner，
因此标准部署必须安装两份 requirements；不要使用 `--no-deps` 强装冲突版本。

## 2. 模型准备

下载只使用 ModelScope 和 Python 标准库 `urllib`：

```bash
python scripts/download_model.py
```

默认主模型为 `Qwen/Qwen3-ASR-0.6B`，固定 revision
`4ce9cc728b473a5aedbe7b6e1ea45646316824dc`，目录为
`models/qwen3-asr-0.6b/vllm`。默认 Aligner 为 `Qwen/Qwen3-ForcedAligner-0.6B`，固定
revision `cf1c50164ea3ac48240d12bef5ead74aee0720cc`，目录为
`models/qwen3-forced-aligner-0.6b/pt`；`run.sh` 会检查并按需下载两者。下载器验证大小和
SHA256，支持 `.part` 原子替换、Linux 文件锁和 manifest。不要手工把其他 revision 覆盖到
同一目录。

### 语种与方言支持

#### Qwen3-ASR 主模型

主模型支持以下 **30 种语言**。`/chinese_asr` 的 `language` 可使用英文名称或括号中的 ISO
代码显式指定；不传或传空值时由模型逐物理分片自动检测：

- Chinese（中文，`zh`）、English（英语，`en`）、Cantonese（粤语，`yue`）、Arabic（阿拉伯语，`ar`）
- German（德语，`de`）、French（法语，`fr`）、Spanish（西班牙语，`es`）、Portuguese（葡萄牙语，`pt`）
- Indonesian（印度尼西亚语，`id`）、Italian（意大利语，`it`）、Korean（韩语，`ko`）、Russian（俄语，`ru`）
- Thai（泰语，`th`）、Vietnamese（越南语，`vi`）、Japanese（日语，`ja`）、Turkish（土耳其语，`tr`）
- Hindi（印地语，`hi`）、Malay（马来语，`ms`）、Dutch（荷兰语，`nl`）、Swedish（瑞典语，`sv`）
- Danish（丹麦语，`da`）、Finnish（芬兰语，`fi`）、Polish（波兰语，`pl`）、Czech（捷克语，`cs`）
- Filipino（菲律宾语，`fil`）、Persian（波斯语，`fa`）、Greek（希腊语，`el`）、Hungarian（匈牙利语，`hu`）
- Macedonian（马其顿语，`mk`）、Romanian（罗马尼亚语，`ro`）

主模型还声明支持以下 **22 种中国方言/口音的自动识别**。这些标签会写入响应 `slid`，但不能
作为当前接口的显式 `language` 参数：

- Anhui（安徽）、Dongbei（东北）、Fujian（福建）、Gansu（甘肃）、Guizhou（贵州）
- Hebei（河北）、Henan（河南）、Hubei（湖北）、Hunan（湖南）、Jiangxi（江西）
- Ningxia（宁夏）、Shandong（山东）、Shaanxi（陕西）、Shanxi（山西）、Sichuan（四川）
- Tianjin（天津）、Yunnan（云南）、Zhejiang（浙江）
- Cantonese (Hong Kong accent)（粤语香港口音）
- Cantonese (Guangdong accent)（粤语广东口音）
- Wu language（吴语）、Minnan language（闽南语）

#### Qwen3 ForcedAligner

ForcedAligner 只支持以下 **11 种标准语言**及对应别名：

- Chinese（中文，`zh`）、English（英语，`en`）、Cantonese（粤语，`yue`）
- French（法语，`fr`）、German（德语，`de`）、Italian（意大利语，`it`）
- Japanese（日语，`ja`）、Korean（韩语，`ko`）、Portuguese（葡萄牙语，`pt`）
- Russian（俄语，`ru`）、Spanish（西班牙语，`es`）

Aligner 不直接接受上述 22 种方言/口音标签。分片 `slid` 为空或不属于这 11 种标准标签时，
服务不会猜测、映射或回退中文，而是保留 ASR 文本与物理分片边界、返回 `words=[]`，并在顶层
`message` 中列出跳过的分片和语种。

## 3. 启动与停止

```bash
bash run.sh
```

脚本先检查端口和依赖、检查/下载模型，再启动 `127.0.0.1:8081` 的 vLLM；健康后启动
`0.0.0.0:8080` 的网关。客户端只访问 8080。任一进程退出时另一个会被清理；按 `Ctrl+C`
统一停止。`run_gateway.sh` 只用于后端已单独运行时调试。

```bash
curl http://127.0.0.1:8080/health
# {"status":"ok","version":"1.1.0","model":"qwen3-asr","timestamps":true,"aligner_device":"cuda:0"}
```

端口冲突：

```bash
ss -ltnp "sport = :8080"
ss -ltnp "sport = :8081"
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

确认旧进程后正常 `kill <PID>`，不要优先使用 `kill -9`。

## 4. 配置参数

系统参数由 `src/config.py` 集中读取和校验；`run.sh` 提供部署默认值。非数字、非布尔、非正
数或未实现开关会在启动阶段明确失败。布尔值支持 `true/false`、`1/0`、`yes/no`、`on/off`。

### 模型与 vLLM

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `SERVICE_VERSION` | `1.1.0` | `/health` 返回的服务版本 |
| `VLLM_MODEL_ID` | `Qwen/Qwen3-ASR-0.6B` | ModelScope 模型 ID |
| `VLLM_MODEL_DIR` | `models/qwen3-asr-0.6b/vllm` | 本地权重目录 |
| `MODELSCOPE_REVISION` | `4ce9cc...24dc` | v1.1.0 固定不可变 revision |
| `MODELSCOPE_ENDPOINT` | `https://modelscope.cn` | 下载器端点；通常无需修改 |
| `SERVED_MODEL_NAME` | `qwen3-asr` | vLLM 服务名及网关缺省模型名 |
| `VLLM_HOST` | `127.0.0.1` | 后端只监听本机，避免绕过网关 |
| `VLLM_PORT` | `8081` | 后端端口；通用 `PORT` 会被忽略 |
| `DTYPE` | `bfloat16` | 模型推理精度 |
| `VLLM_LOAD_FORMAT` | `safetensors` | 本地权重加载格式 |
| `VLLM_GPU_MEMORY_UTILIZATION` | `0.85` | vLLM 固定默认显存预算；调用方显式值优先 |
| `VLLM_MAX_MODEL_LEN` | `10240` | 最大上下文长度，不等于固定音频秒数 |
| `VLLM_MAX_NUM_SEQS` | `128` | scheduler 最大活跃序列数 |
| `VLLM_MAX_NUM_BATCHED_TOKENS` | `10240` | 单轮调度 token 预算 |
| `VLLM_MAX_AUDIO_CLIP_FILESIZE_MB` | `96` | vLLM 多模态加载器接收的单个音频剪辑文件上限（MiB）；不限制整条网关请求时长，长音频会先按 `AUDIO_CHUNK_SECONDS` 切片 |
| `VLLM_ATTENTION_BACKEND_NAME` | `FLASH_ATTN` | attention 后端 |
| `VLLM_STARTUP_TIMEOUT` | `600` | `run.sh` 等待后端健康的秒数 |

### 网关与业务

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `GATEWAY_HOST` | `0.0.0.0` | 对外监听地址 |
| `GATEWAY_PORT` | `8080` | 唯一对外端口 |
| `BACKEND_URL` | `http://127.0.0.1:8081` | vLLM 地址 |
| `LOG_LEVEL` | `INFO` | 网关结构化日志级别：`DEBUG/INFO/WARNING/ERROR/CRITICAL` |
| `LOG_FILE_ENABLED` | `true` | 是否额外写入本地轮转文件；stdout 始终保留 |
| `LOG_DIR` | `logs` | 文件日志目录；Compose 使用 `/var/log/qwen3-asr` |
| `LOG_MAX_FILE_MB` | `200` | 单个 `gateway.log` 文件大小上限（MiB）；当前文件加 7 个备份的理论容量上限约 1.6 GiB |
| `LOG_BACKUP_COUNT` | `7` | 最多保留的大小轮转备份数；总容量有硬上限 |
| `LOG_RETENTION_DAYS` | `7` | 每次启动清理超过该天数的轮转文件及旧 PID 日志 |
| `LOG_QUEUE_SIZE` | `10000` | 异步日志队列容量；队列满时不阻塞请求并统计丢弃数 |
| `AUDIO_CHUNK_SECONDS` | `32` | 长音频固定分片上限 |
| `MAX_AUDIO_SECONDS` | `2000` | 解码后按采样帧计算的单条原音频最大时长 |
| `MAX_UPLOAD_MB` | `280` | Base64 解码后或 multipart 音频文件字节上限（MiB） |
| `MAX_JSON_BODY_MB` | `280` | 整个 Base64 JSON HTTP 请求体上限（MiB） |
| `CHUNK_CONCURRENCY` | `3` | 单个长请求的分片 fan-out 上限 |
| `LONG_CHUNKS_IN_FLIGHT` | `96` | 全局长分片在途上限；短音频不占用 |
| `BACKEND_TIMEOUT` | `300` | 单个后端分片超时秒数 |
| `ENABLE_HOTWORD` | `true` | 是否将客户端热词写入 Prompt |
| `MAX_HOTWORDS` | `100` | 去空去重后的最大热词数 |
| `MAX_HOTWORD_LENGTH` | `64` | 单个热词最大字符数 |
| `MAX_HOTWORD_CHARS` | `1000` | 所有热词最大总字符数 |
| `ENABLE_VAD` | `false` | 未实现；设为 true 时拒绝启动 |
| `ENABLE_WORD_TIMESTAMP` | `true` | 默认为 `/chinese_asr` 返回 Aligner 字/词级 `words[]` |
| `ENABLE_SENTENCE_TIMESTAMP` | `true` | 默认按主模型标点把 `/chinese_asr asr[]` 聚合为句级 |
| `ALIGNER_MODEL_DIR` | `models/qwen3-forced-aligner-0.6b/pt` | ForcedAligner 本地权重目录 |
| `ALIGNER_DEVICE` | `cuda:0` | Aligner 设备；单 A10 同卡试验使用 `cuda:0` |
| `ALIGNER_DTYPE` | `bfloat16` | Aligner 精度；CPU 必须使用 `float32` |
| `ALIGNER_CONCURRENCY` | `1` | 同时对齐任务数；同卡建议保持 1 |
| `ALIGNER_BATCH_SIZE` | `1` | 单次对齐分片数；同卡建议保持 1 |

默认上限为 2000 秒、解码后音频 280 MiB、完整请求体 280 MiB。Base64 会膨胀约 1/3，
因此 `/chinese_asr` 的 280 MiB JSON 最多承载约 210 MiB 原始音频；multipart 还会产生边界
和字段开销。时长只有解析音频后才能获知，两层字节限制仍负责在 HTTP 接收和解码阶段保护内存。

当前部署默认是 `CHUNK_CONCURRENCY=3`、`LONG_CHUNKS_IN_FLIGHT=96`，与历史 A10 纯 90 秒
最高吞吐组合一致；默认同卡 Aligner 和 0～2000 秒混合流量仍必须重新验证显存、吞吐和 P95/P99。

### 默认 ForcedAligner 时间戳

```bash
python -m pip install -r requirements-aligner.txt
python -m pip check
bash run.sh
```

`run.sh` 会仅从 ModelScope 下载 `Qwen/Qwen3-ForcedAligner-0.6B` 的固定 revision。单 A10
同卡实际是 vLLM 与网关中的 Aligner 两个 CUDA 进程；默认使用 `cuda:0/bfloat16/1/1`，且调用方
未显式设置显存预算时 vLLM 使用 `0.85`。ForcedAligner 只支持 Chinese、English、Cantonese、
French、German、Italian、Japanese、Korean、Portuguese、Russian、Spanish。请求未传
`language` 时，主模型逐物理分片自动检测，并将检测标签直接用于对齐。支持的分片执行真实
对齐；语种为空或为 Malay、Arabic 等非上述 11 种语言的分片会显式跳过对齐，但不会中断
ASR：接口返回 HTTP 200，保留该分片的 `text`、`slid` 和物理边界，`words=[]`，顶层
`message` 列出跳过的分片与语种。服务不回退到 Chinese。

如果启用了句级时间戳但存在任一跳过分片，整条响应保留物理分片结构，顶层 `message` 同时
说明句级聚合已禁用；只有全部非空分片均成功对齐时才返回句级 `asr[]`。

若只需识别其他主模型语言而不需要真实字/词时间戳，可关闭两个开关后重启：

```bash
ENABLE_WORD_TIMESTAMP=false ENABLE_SENTENCE_TIMESTAMP=false bash run.sh
```

此时 ASR 正常返回，`slid` 仍是主模型逐片标签，`timestamp` 仅表示物理分片边界，`words=[]`。
默认同卡双模型必须用 `nvidia-smi` 检查峰值并验证 OOM、吞吐和 P95/P99。
`run_gateway.sh` 不安装依赖、不下载模型，只用于后端和权重已准备好的独立调试。

### Docker 镜像

发布镜像默认 `INSTALL_ALIGNER=true`，两个时间戳开关也默认开启。Dockerfile 会把 `models`、
`tests`、`test_data` 复制进镜像；构建前必须准备完整的主模型和 Aligner 固定 revision 权重及
`.modelscope-manifest.json`：

```bash
python scripts/download_model.py
python scripts/download_model.py \
  --model-id Qwen/Qwen3-ForcedAligner-0.6B \
  --dir models/qwen3-forced-aligner-0.6b/pt \
  --revision cf1c50164ea3ac48240d12bef5ead74aee0720cc

docker build --no-cache --build-arg INSTALL_ALIGNER=true \
  -t qwen3-asr-infer:0.16.0 .
docker run -d --gpus '"device=0"' --restart=always \
  -p 8080:8080 qwen3-asr-infer:0.16.0
```

Compose 默认只拉取 `zhxgharbor.istarshine.com/asr/qwen3-asr-infer:0.16.0`，不执行本地构建：

```bash
docker compose up -d --force-recreate
```

`INSTALL_ALIGNER=false` 仍可构建不含 qwen-asr 的定制镜像，但运行时必须同时显式关闭两个
`ENABLE_*_TIMESTAMP`，否则 `run.sh` 会在启动前明确失败。私有 vLLM 基础镜像若包含 distutils
安装的 `blinker 1.4`，Dockerfile 会先移除系统包残留，再以 `--ignore-installed` 固定覆盖为
`blinker==1.9.0`；不要删掉该步骤或跳过 `pip check`。

## 5. 结构化日志与 API 调用

网关请求协程只把 `LogRecord` 放入容量为 `LOG_QUEUE_SIZE` 的内存队列，独立监听线程负责
格式化并写 stdout 和可选文件，避免慢磁盘或容器 stdout 背压直接阻塞 aiohttp 事件循环。文件
固定为 `LOG_DIR/gateway.log`，达到 `LOG_MAX_FILE_MB` 后按 `.1`、`.2` 等滚动，最多保留
`LOG_BACKUP_COUNT` 份；启动时还会清理超过 `LOG_RETENTION_DAYS` 天的备份及旧版
`gateway_<pid>.log*`。因此文件日志同时受大小、份数和时间约束，跨进程重启仍能清理。

Compose 使用命名卷 `asr-logs` 持久化文件日志；`docker compose down` 默认保留该卷，只有
`docker compose down -v` 才删除。`run.sh` 保留容器 stdout 专门输出网关 JSON，并把启动提示、
下载器和 vLLM 文本统一送到 stderr；Docker 日志记录保留 `stdout/stderr` 来源，虽然
`docker compose logs` 默认会合并展示。Compose 的 `json-file` 驱动默认按
`DOCKER_LOG_MAX_SIZE=100m`、`DOCKER_LOG_MAX_FILES=5` 对两条流统一实施容器级轮转，不受应用
日志参数控制。

每条网关日志包含 `timestamp`、`level`、`logger`、`event`、`message`、`request_id`。请求完成
事件保留 `input_fields`、`output_fields`、HTTP 状态、结果分类、总耗时以及音频大小/时长、
分片数、语言模式和结果字符数等统计摘要；`/chinese_asr` 还包含结构化 `input_json` 和
`result_json`。`input_json.base64` 仅保留前 64 个 ASCII 字节，完整 Base64 长度由
`base64_encoded_chars` 记录；成功和业务错误响应都会写入 `result_json`。业务 JSON 仍受日志
字符串、集合和嵌套上限约束，超限项会明确标记截断。取消或断连使用观测状态 `499`。4xx/5xx
记录业务错误码或异常类型，代理端点额外记录上游状态和响应字节数。`DEBUG` 级别记录后端逐
分片耗时，并记录成功的健康检查/指标/模型列表请求；默认 `INFO` 不保存这些高频管理端点的
成功访问。

队列满时请求不会等待日志 I/O；被丢弃的数量会附加在下一条成功日志的
`dropped_logs_before`，进程关闭时仍未上报的数量写入 `log_records_dropped_on_shutdown`。文件或
stdout 写入失败后，对应 handler 会被停用并输出不含业务字段的固定内部错误事件，避免反复打印
logging traceback。正常退出会先排空队列再关闭文件。

日志会记录 `/chinese_asr` 的热词、`article_url`、语言和识别结果等业务内容；输入音频
Base64 只保留前 64 字节，不记录其余 Base64 或解码后的音频二进制。multipart 文件名和后端
Prompt 也不落日志。必须把 stdout、日志采集系统和命名卷按敏感数据管理，限制访问权限，并按
业务要求设置 `LOG_RETENTION_DAYS`。现有字段名、音频大小/时长、分片、语言、结果计数、
错误码、状态和耗时等统计摘要仍全部保留。定位问题时使用响应头 `X-Request-ID` 查询：

```bash
docker compose logs qwen3-asr | grep '<request-id>'
docker compose exec qwen3-asr grep '<request-id>' /var/log/qwen3-asr/gateway.log*
```

完整字段、成功/失败样例、错误码和响应头见 [API 文档](API文档.md)。

```bash
AUDIO_BASE64="$(base64 -w 0 test_data/audio_16000_10s.wav)"
curl http://127.0.0.1:8080/chinese_asr \
  -H 'Content-Type: application/json' \
  -d "{\"base64\":\"$AUDIO_BASE64\",\"article_url\":\"source-001\",\"hotwords\":[\"通义千问\"]}"

curl http://127.0.0.1:8080/v1/audio/transcriptions \
  -F file=@test_data/audio_16000_10s.wav -F model=qwen3-asr
```

## 6. 测试与 CER

```bash
python tests/test_chinese_asr_single.py --audio test_data/audio_16000_10s.wav
python tests/test_service.py --api-mode chinese-asr \
  --audio test_data/audio_16000_30s.wav --concurrency 96 --total 2000
python tests/verify_qwen_single.py --api-mode chinese-asr \
  --input test_data --ref test_data --baseline-cer 0.05
```

CER 门禁要求参考覆盖 `--limit` 处理后的全部输入，且每条参考经 NFKC、去空白后非空；缺失、
空参考或零计分样本均非零退出。目录参考使用同名 `.txt`；单文件参考用 `.txt`；JSONL 每行
包含字符串 `wav`、`text`，相对音频路径以 JSONL 所在目录解析；直接文本使用 `--ref-text`。

## 7. 排障

- Docker 构建在 `pip check` 报 `pygobject ... requires pycairo`：这是私有 vLLM 基础镜像预装
  PyGObject 但缺少系统依赖；Dockerfile 已安装 `python3-cairo`，不应删除或忽略 `pip check`。
- Docker 构建提示 `/bin/sh: python: not found`：部分 vLLM 基础镜像只提供 `python3` 或
  `python3.12`；当前 Dockerfile 会自动探测解释器并创建 `/usr/local/bin/python` 兼容入口。
  请确认使用最新 Dockerfile 后以 `--no-cache` 重新构建。
