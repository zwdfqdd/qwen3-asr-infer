# 性能优化实验台账

本文件是 `dev` 分支从 v2.0.0 演进到 v3.0.0 的追加式证据索引。策略定义、架构瓶颈、测试矩阵
和准入规则见[性能调优](性能调优.md)。未经目标 Linux/CUDA 实测的内容不得标记为“采纳”。

## 管理规则

- 实验 ID 使用 `PERF-<领域>-<三位序号>`，创建后不得复用；历史导入使用 `HIST-` 前缀。
- 状态只允许：`候选`、`就绪`、`测试中`、`采纳`、`拒绝`、`阻塞`。
- 一次只改变一个主要变量；多因素实验必须提前写明矩阵与交互假设。
- 每组至少预热 3 条、执行 3 轮，使用中位数决策，同时保留最差一轮。
- 拒绝和阻塞记录不删除；硬件、vLLM 或模型版本变化后可新建 ID 重新验证。
- 原始音频、模型、完整业务日志和敏感正文不进入 Git；提交去敏摘要、SHA256 和决策。
- 只有“采纳”且构成重要里程碑的提交创建带注释 tag，失败实验不打 tag。

## PERF-OBS-002：网关阶段与排队耗时

- 状态：就绪
- 日期：2026-07-27
- 假设：统一的服务端阶段计时可以区分网关 CPU、分片排队、HTTP/vLLM 和 Aligner 瓶颈。
- 实现：完成日志 `stage_timings_ms` 与 `Server-Timing` 共用 14 个固定指标；分片本地/全局
  信号量记录累计与最大等待，`asr-backend` 记录分片 HTTP 累计，`asr`/`total` 记录墙钟；
  Aligner 返回独立 queue/inference 耗时，JSON 成功和错误响应统一测量序列化。
- 安全性：分片等待全局槽时若取消或异常，会释放已获得的本地槽；后端完成或失败后按获得状态
  释放两级信号量，不改变原有并发预算。
- 无 GPU 验证：假 vLLM 覆盖 `/chinese_asr` 和 multipart，响应 JSON/错误契约不变；14 个阶段
  均为有限非负数，压测器严格解析并实现 100% 覆盖门禁。
- 门禁结论：实现 GO；真实并发下计时开销、vLLM 指标相关性和 Aligner 排队仍待目标 GPU 验证。
- 回滚：移除响应头和细分计时但保留原请求总耗时；任何可测吞吐退化超过门禁时不得采纳。

## PERF-NET-001：后端瞬时连接失败诊断与 keep-alive 修复

- 状态：采纳。
- 日期：2026-07-28。
- 触发证据：`PERF-BASE-001` 三轮共出现 5/6000 个 `MODEL_LOAD_FAILED`，失败均在约 2 ms
  后端阶段内结束。
- 诊断结果：增强 cause 链日志后，诊断轮失败请求 `044bb13a388748f8ae907d2dbb0a4bc9`、
  `00831200414947039ed184f56b8a63fe` 均为 `root_exception_type=ServerDisconnectedError`、
  `exception_cause_depth=1`，无 errno；另一轮请求 `d9e8438fd0fb47bfb2e5189822c8874b` 也返回
  `MODEL_LOAD_FAILED`，须以对应新日志确认，但已有重复证据足以排除 TCP 建连拒绝和模型计算错误。
- 修复前诊断轮：一轮 1998/2000、110.58 audio_s/s、P95 8932.6 ms、P99 9015.9 ms；另一轮
  1999/2000、107.24 audio_s/s、P95 9483.0 ms、P99 10181.1 ms。两次使用同一输出路径，后一次
  已覆盖前一次 JSON；台账保留终端摘要，后续报告必须使用独立文件名。
- 对照说明：未指定 `--api-mode` 的命令默认测试 multipart `/v1/audio/transcriptions`，得到
  2000/2000、136.72 QPS、1367.17 audio_s/s、P95 730.1 ms。其 `base64-decode=0`、
  `aligner-queue=0`、`aligner=0`，并使用 Transcriptions API 而非自动语种 Chat API，因此它是
  不同接口和不同功能负载，不能证明“参数少更稳定”，也不能直接替代 `/chinese_asr` 基线。
- 根因假设：aiohttp 固定版本默认连接池上限为 100、空闲连接保留 15 秒；默认时间戳路径被串行
  Aligner 限制到约 11 QPS，客户端请求约 8～9 秒后才补发，池内部分连接可能先被 vLLM 关闭。
  网关复用该连接时收到 `ServerDisconnectedError`。native 路径约 137 QPS，连接复用间隔更短，
  因而该轮没有触发同一竞态。
- 候选修复：新增 `BACKEND_CONNECTION_LIMIT=100` 和 `BACKEND_KEEPALIVE_TIMEOUT=4`；网关使用
  显式 `TCPConnector(limit=100, limit_per_host=100, keepalive_timeout=4)`，保持原连接容量不变，
  只让客户端先于 vLLM 淘汰空闲连接。继续记录底层异常类型和失败请求 ID，不自动重试 POST。
