# 性能优化实验台账

本文件是 `dev` 分支从 v2.0.0 演进到 v3.0.0 的追加式证据索引。策略定义、架构瓶颈、测试矩阵
和准入规则见[性能调优](性能调优.md)。未经目标 Linux/CUDA 实测的内容不得标记为“采纳”。

## 管理规则

- 实验 ID 使用 `PERF-<领域>-<三位序号>`，创建后不得复用；历史导入使用 `HIST-` 前缀。
- 状态只允许：`候选`、`就绪`、`测试中`、`采纳`、`拒绝`、`阻塞`。
- 一次只改变一个主要变量；多因素实验必须提前写明矩阵与交互假设。
- 每组至少预热 3 条、执行 3 轮，使用中位数决策，同时保留最差一轮。
- 拒绝和阻塞记录不删除；硬件、vLLM 或模型版本变化后可新建 ID 重新验证。
- 原始音频、模型、完整业务日志和敏感正文不进入 Git；提交去敏摘要、SHA256 和决策。
- 只有“采纳”且构成重要里程碑的提交创建带注释 tag，失败实验不打 tag。

## PERF-OBS-002：网关阶段与排队耗时

- 状态：就绪
- 日期：2026-07-27
- 假设：统一的服务端阶段计时可以区分网关 CPU、分片排队、HTTP/vLLM 和 Aligner 瓶颈。
- 实现：完成日志 `stage_timings_ms` 与 `Server-Timing` 共用 14 个固定指标；分片本地/全局
  信号量记录累计与最大等待，`asr-backend` 记录分片 HTTP 累计，`asr`/`total` 记录墙钟；
  Aligner 返回独立 queue/inference 耗时，JSON 成功和错误响应统一测量序列化。
- 安全性：分片等待全局槽时若取消或异常，会释放已获得的本地槽；后端完成或失败后按获得状态
  释放两级信号量，不改变原有并发预算。
- 无 GPU 验证：假 vLLM 覆盖 `/chinese_asr` 和 multipart，响应 JSON/错误契约不变；14 个阶段
  均为有限非负数，压测器严格解析并实现 100% 覆盖门禁。
- 门禁结论：实现 GO；真实并发下计时开销、vLLM 指标相关性和 Aligner 排队仍待目标 GPU 验证。
- 回滚：移除响应头和细分计时但保留原请求总耗时；任何可测吞吐退化超过门禁时不得采纳。
## PERF-BASE-001 / short-default-run-01：10 秒默认时间戳基线

- 状态：测试中；本记录是三轮中的第 1 轮，不代表最终基线或优化结论。
- 日期：2026-07-28
- 代码：服务端至少包含 `70a11a8` 的阶段计时，压测器包含 `2e2682a` 的机器报告；精确提交、
  GPU 型号、驱动/CUDA 和依赖版本应以生成的 JSON 报告为准。
- 条件：`/chinese_asr`、10.000 秒、1 个物理分片、默认时间戳、客户端并发 96、总请求 2000。
- 结果：1999 成功、1 失败，成功率 99.95%；失败为 HTTP 500 `MODEL_LOAD_FAILED`，因此未通过
  成功率 100% 门禁。总耗时 179.70 秒，11.12 QPS，11.12 分片 RPS，111.24 audio_s/s。
- 端到端：平均 8497.4 ms，P50 8730.3 ms，P90 8845.5 ms，P95 8860.2 ms，P99 8921.5 ms。
- 服务端：`total` 平均 8487.17 ms/P95 8857.35/P99 8918.64；客户端与服务端平均差约
  10.23 ms，传输和压测器附加耗时不是主要瓶颈。
- ASR：`asr` 平均 436.56 ms/P95 1307.15/P99 2801.46；`asr-backend` 平均 433.62 ms。
- Aligner：排队平均 7949.93 ms/P95 8436.12/P99 8492.51，占服务端平均总耗时约 93.67%；
  推理平均 88.02 ms/P95 95.29/P99 101.20，占约 1.04%。按 88.02 ms 串行服务时间估算容量约
  11.36 req/s，与实测 11.12 QPS 接近，当前主要瓶颈是 `ALIGNER_CONCURRENCY=1` 的跨请求串行。
- 其他：请求解析平均 10.73 ms，但 P95 2.71 ms、P99 328.26 ms，说明少量长尾拉高均值，需从
  JSON 的 max 和后续两轮确认；Base64、切片、后处理和序列化平均合计不足 2 ms。
- 资源：GPU 平均 97.6%、峰值 100%、显存峰值 19117 MiB；CPU 平均 10.8%、峰值 27.0%。
  在尝试 Aligner 并发或微批前必须确认 GPU 型号/总显存和安全余量，防止 OOM。
- 计时质量：1999/1999 成功响应 `Server-Timing` 覆盖率 100%，阶段和 `total` 的平均值基本闭合。
- 门禁结论：NO-GO。原因是存在 1 个后端连接类失败、仅执行 1 轮，且默认时间戳基线矩阵未完成。
- 下一步：先从网关日志定位 `MODEL_LOAD_FAILED` 对应的 `backend_chunk_failed`；随后以相同条件
  完成 run-02/run-03。三轮稳定后再执行关闭时间戳的 ASR-only 对照，量化 Aligner 总税负；
  在此之前不直接提高 `ALIGNER_CONCURRENCY`，也不把单轮结果升级为 `PERF-ALI` 采纳结论。
